전체 Career 13+4 실행은 별도 검증 저장소에서 수행했다. 운영에서는 기본 실험 실행,
Equity worker smoke, 전체 모듈 readiness 및 기존 증거 조회를 검증했다.
별도 검증 실행을 운영 이력과 합치거나 운영에서 13+4를 다시 실행한 것으로 해석하지 않는다.

첫 기본 브라우저 묶음의 1건 생략은 인수 경로가 없던 `local-deployment.spec.ts`다.
전체 Career 인수 완료 후 실제 17개 Run으로 별도 실행해 통과했고, 운영 회귀 34건은 생략 0건이다.
초기 셸 PATH가 Node 23/npm 10이어서 서비스 설치가 이를 거절했다. 기존 Node 24와
캐시 npm 11.6.0을 명시해 빌드·회귀를 다시 수행했으며 production 산출물 hash는 동일했다.
이관 확인 스크립트의 `bytes`/`size` 필드명 차이도 수정 후 전체 파일을 재대조했다.
확인 실패를 통과로 처리하거나 런타임 버전 검사를 우회하지 않았다.

## 증거와 한계

로컬 기록은 `.lab/verification/v0.2.0/`와 배포 경로에 보존한다.
`migration.json`, `final-audit.json`, `cleanup-verification.json`, `backup-last-success.json`이
운영 이관·해시·정리·백업 근거다. `acceptance/index.json`은 이관한 기존 Career 17개 기록이며,
`acceptance/operating-smoke.json`은 새 운영 Equity 실행이다. 신규 전체 인수는
`staging-acceptance/index.json`·`reopen.json`·`contracts.json`에서 확인한다.
검증용 프로세스는 종료하고 저장소·백업·배포 이미지·증거는 보존했다.
다른 프로젝트 컨테이너는 중지하거나 제거하지 않았다.

실제 화면 3장과 사용 절차는 [대시보드 가이드](../standalone-dashboard.md#v020-전체-모듈에서-패턴-활용)에 있다.
구형 Run에 측정 계약을 백필하지 않으며, 패턴 일치를 성능 우위로 판정하지 않는다.
이번 재시작 검증은 정상 종료/재개방과 백업에 의한 재기동이다. privileged Docker daemon
장애, 실제 로그아웃·호스트 재부팅, 외부 공개 환경을 다시 시험한 결과가 아니다.
기존 [운영 제한](v0.2.0.md#사용-및-확장-문서)과 [실패 주입 검증 범위](../worker-fault-injection.md)를 유지한다.

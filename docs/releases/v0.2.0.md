# Engineering Lab v0.2.0

릴리스 준비: 2026-10-18 (Asia/Seoul). 패턴 중심 플랫폼 P1–P6의 소스 릴리스다.
운영 전환과 실제 검증 결과는 P7 배포 기록에 구분해 기록한다.

## 변경 사항

- 기존 16개 실험을 분야·패턴·프로젝트 출처로 탐색한다. 패턴 API가 없는 구형 서버는
  모듈별 탐색으로 돌아가며 기존 실행·기록 URL을 유지한다.
- Strategy/Case study/Scenario 등록으로 구현 전략, 사례 근거와 한계, 원본 시나리오
  정의 다운로드를 연결한다. FACT 기반 재현과 NEW-DESIGN을 구분한다.
- 신규 Run은 검증 성질·측정 범위·단위의 optional 계약을 저장한다. 비교 화면은
  기록된 조건의 차이와 누락을 보여준다. 패턴 일치나 CHECK 통과로 성능 우위를 판정하지 않는다.
- Excel과 Equity가 Java 21 무의존 `BoundedBatch`를 공유한다. 각 실험의 트랜잭션,
  재시도·DLQ·시간 flush·종료 정책은 유지한다. Equity 전체 입력 List는 여전히 메모리에 있다.
- 선택 활성화 `examples.batched-checksum`이 중앙 API/프론트엔드 분기 없이 패턴 재사용을
  검증한다. 기본값은 비활성이고 운영의 기존 16개 실험 구성은 유지한다.

## 호환 및 업그레이드

기존 experiment/module/scenario/metric ID, 원본 정의의 canonical hash, 저장 schema v3와
worker 통신 v1은 유지한다. 과거 Run에는 측정 계약을 백필하지 않으며 비교 조건은
UNKNOWN으로 남긴다. 원시 증거·REPORT 다운로드와 기존 비교/export는 계속 사용할 수 있다.

1. [백업](../local-backup.md) 후 별도 경로에 복원해 기존 이력을 확인한다.
2. [전체 모듈 배포](../local-deployment.md)의 순서로 Career → 루트 → frontend를 빌드한다.
   Equity worker에는 새 `pipeline-support`가 포함되므로 기존 v0.1.0 worker 이미지를 재사용하지 않는다.
3. 새 디렉터리·별도 포트에서 정상/실패 실행, 재시작, artifact 다운로드를 검증한다.
4. 최신 백업의 store를 이관하고 [상시 서비스](../local-service.md)와 백업 예약을 새 배포로 전환한다.
   기존 배포·백업·이미지는 보존한다. 되돌리기 전 새 실행 이력도 백업한다.

소스 릴리스 태그는 `v0.2.0`이다. Gradle 개발용 SNAPSHOT, Career jar 파일명 및 frontend의
내부 package 버전은 기존 계약대로 유지한다. Docker 이미지·로컬 Run 데이터는 공개 릴리스에 첨부하지 않는다.

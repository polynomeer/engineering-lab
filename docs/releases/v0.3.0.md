# Engineering Lab v0.3.0

릴리스 날짜: 2026-10-24 (Asia/Seoul). 반복 측정과 증거 묶음 중심의 소스 릴리스다.
운영 전환과 실제 검증 결과는 [운영 전환 기록](v0.3.0-deployment.md)에 구분해 기록한다.

## 변경 사항

### 측정을 믿을 수 있게

- 반복 측정(`/run-series`): 같은 정의를 warmup 후 N회 순서대로 실행하고 measure별
  중앙값·p95(nearest rank)·표본 표준편차·변동 계수를 낸다. 두 묶음은 관측 범위 겹침으로만
  비교하며 통계적 유의성 검정이 아니다.
- 기준선 지정과 회귀 판정(CLI 종료 코드 3 회귀, 4 판정 불가), 파라미터 스윕(`/run-sweeps`,
  파라미터 4개·점 24개·Run 300개 상한, 1차원 선 그래프·2차원 heatmap).
- 묶음이 측정하는 동안 다른 경로의 Run 접수는 409로 거절한다(`lab.series.exclusive`).
  그래도 겹친 Run, 변동 계수 10% 초과 measure, 반복마다 판정이 달라진 CHECK는 묶음 상세와
  Finding 초안에 경고한다. 모든 Run summary에 호스트 1분 부하와 CPU 사용률을 남긴다.
- Excel 측정 계약 1.1.0: 저장 처리량과 20 ms 표본 최대 heap을 measure로 추가했다.
  `forkedHeapMiB`(32–8192)를 주면 실행마다 `-Xmx`를 건 자식 JVM에서 처리해 heap이
  그 실행만의 값이 된다. 서버 안에서 실행한 heap은 JVM 전체 값임을 계약에 적었다.
- 반복 묶음·스윕 중지. 실행 중인 Run은 끝까지 돌고 다음 반복부터 멈춘다.

### 증거를 남기고 공유하게

- 증거 묶음 zip(`/evidence-bundles`): Run export, 크기·SHA-256을 검증한 캡처,
  묶음 통계·비교, Finding 초안, manifest, `SHA256SUMS`.
- Finding 초안 내려받기. 기록된 사실만 채우고 문제·해석·결정은 `<작성 필요>`로 남긴다.
- 기준선 파일 내보내기와 파일 기준 회귀 판정(`--check-baseline-file`), 야간
  Performance regression 워크플로. 측정 환경이 다르면 판정에 주의 문구를 붙인다.
- `docs/findings`가 인용한 Run을 Run 상세에 표시하고 보관 정리에서 제외한다.
- 오래된 JFR·Run 로그 캡처 정리(`/maintenance/retention`): 미리보기 token과
  `lab.retention.apply-enabled=true`가 있어야 삭제한다. 기준선·Finding 인용 Run은 제외한다.

### 대시보드와 배포

- 기본 `bootJar`가 React 대시보드를 `/app`에 내장하고, 기존 화면 주소는 기본으로 `/app`에
  전환한다(`lab.dashboard.redirect-enabled=true`). 패키징에 Node 24가 필요하며
  `-PskipFrontend`로 API만 만들 수 있다.
- 요약 지표·파이프라인 흐름·dead-letter 화면, 반복 측정·스윕 화면, Excel 워크북을 받는
  조건 지정 실행 폼, 서버 측 시나리오·상태 필터.
- 진입점이 `com.pnomeer.lab.EngineeringLabApplication`으로, 실행 jar 이름이
  `engineering-lab-*.jar`로 바뀌었다.

## 호환 및 업그레이드

저장 schema가 v3에서 **v4**로 올라간다(`lab_series`, `lab_series_run`, `lab_series_baseline`,
`lab_sweep`, `lab_sweep_point`). 시작할 때 `<storage-root>/backups/schema-v3-before-v4-<UUID>.zip`을
먼저 원자적으로 만든 뒤 이행한다. 기존 Run 행·metadata·artifact는 바꾸지 않는다.
v4 저장소는 v0.2.0 이하 서버가 열 수 없다. 되돌릴 때는 이행 전 백업이나 배포 백업을 복원한다.

experiment/module/scenario ID, 원본 정의의 canonical hash, worker 통신 v1은 유지한다.
과거 Excel Run은 실행 당시의 측정 계약(1.0.0)으로 해석하며 새 measure를 백필하지 않는다.

1. [백업](../local-backup.md) 후 별도 경로에 복원해 v4 이행과 기존 이력을 확인한다.
2. [전체 모듈 배포](../local-deployment.md)의 순서로 Career → 루트(대시보드 내장) → frontend를 빌드한다.
3. 새 디렉터리·별도 포트에서 기존 이력 조회, 정상·실패 실행, 반복 측정, 재시작을 검증한다.
4. 최신 백업의 store를 이관하고 [상시 서비스](../local-service.md)와 백업 예약을 새 배포로 전환한다.
   기존 배포·백업·이미지는 보존한다.

## 다음 릴리스에서 제거

- 기존 Java 내장 화면(`/ui`, `/ingest/ui` 등). 이번 릴리스까지 `?legacy=true`로 열 수 있고
  화면에 제거 안내를 표시한다.
- `bootDashboardJar` Gradle task 별칭. `bootJar`를 쓴다.

v0.1.0의 [운영 제한](v0.1.0.md#운영-제한)은 유지한다. 단일 호스트 loopback 배포이며,
외부 공개 인증·TLS, Docker 자동 기동, 외부 백업, 로그 회전·알림은 포함하지 않는다.

# Engineering Lab v0.1.0

릴리스 날짜: 2026-10-16 (Asia/Seoul)

기존 Excel·큐·IO 실험과 Career Lab의 다섯 모듈을 독립 대시보드에서 실행하고,
검증 결과·측정값·환경·REPORT를 보존하는 첫 소스 릴리스다.

## 포함된 기능

- 기존 실험 3개와 Career 5개 모듈/13개 시나리오의 확장 가능한 등록 구조.
- Java 25/Spring Boot 4 플랫폼과 Java 21/Spring Boot 3.3.4 Career 빌드 경계 유지.
- 독립 React 대시보드: 실행 폼, readiness, 실행 기록·비교·내보내기, 최근 실행,
  CHECK 중심 결과 보기, 모바일 탐색, 관리 REPORT 다운로드.
- worker/controller 환경 분리, 컨테이너 실행·소유권 확인·제한된 자원 정리·재시작 복구.
- H2 v3 Run/CHECK 저장과 관리 artifact의 크기·경로·SHA-256 검증.
- 이미지 ID·jar hash를 고정하는 로컬 배포 준비·실행·전체 모듈 인수 도구.
- macOS LaunchAgent의 로그인 자동 시작, 프로세스 종료 후 재기동, 중지·제거 도구.
- 서비스 정지·저장소 잠금·hash 검증·재개를 묶은 백업, 최근 백업 보존,
  기존 배포를 덮어쓰지 않는 별도 경로 복원 및 정기 백업 예약.

## 설치와 업그레이드

[전체 모듈 배포](../local-deployment.md), [상시 실행](../local-service.md),
[백업·복원](../local-backup.md) 가이드를 따른다.

1. 이 태그를 checkout하고 Java 25/21, 고정 Node/npm, Docker 및 캐시 이미지를 준비한다.
2. 기존 운영 배포를 백업한다. 실행 중 store를 직접 복사하거나 덮어쓰지 않는다.
3. Career와 루트 Gradle 빌드는 순차 실행하고 frontend를 빌드한다.
4. 새 배포 디렉터리를 준비하고 별도 포트에서 검증한 뒤 운영 서비스를 전환한다.
5. 새 배포에 서비스·백업 예약을 등록한다. 이전 배포와 백업은 되돌리기 위해 보존한다.

`v0.1.0`은 저장소 전체의 소스 릴리스 태그다. 루트 Gradle의 개발용
`0.0.1-SNAPSHOT`과 Career jar 버전·파일명은 기존 배포 계약대로 유지한다.
GitHub에는 소스 릴리스를 게시하며 Docker 이미지·설치 바이너리·로컬 데이터는 첨부하지 않는다.
태그 push나 릴리스 게시가 현재 실행 중인 고정 배포물을 자동 교체하지 않는다.

## 운영 제한

- 단일 호스트 loopback 배포 기준이다. 외부 공개를 위한 인증·HTTPS·접근 제어는 별도 구성이다.
- LaunchAgent와 예약 백업은 로그인 세션을 사용한다. 실제 로그아웃/호스트 재부팅 시험은 하지 않았다.
- Docker Desktop 자동 시작, health watchdog, 자동 알림, 운영 로그 회전은 포함하지 않는다.
- 백업은 기본적으로 같은 로컬 디스크에 저장하며 Docker 이미지·원본 XLSX·메모리 ingestion DB를 포함하지 않는다.
  디스크 장애 대비 외부 보관과 이미지 배포는 별도 준비한다.
- worker 관측은 현재 capability에 표시된 항목만 지원한다. workspace 접수 예산은 파일시스템 hard quota가 아니다.
- Career 일부 시나리오는 합성 부하·외부 서비스 stub 기반이다. CHECK 통과를 실제 서비스의 성능 보장으로 해석하지 않는다.

다음 개선 후보는 외부 백업 저장소, 운영 로그 보존·용량 알림, 배포 환경별 공개 서비스 구성이다.
